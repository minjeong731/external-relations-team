# 인허가 검토 통합관리 · PC 공동저장 서버

**원하는 방식:** 사내 PC를 임시 서버로 사용하고, 그 PC를 켠 동안 직원들이 같은 데이터를 조회합니다.

- 웹 화면: 기존 디자인을 PC에서 함께 제공합니다.
- API: `server/app.py`와 `server/lan_app.py`
- 실행: `server/start_lan.py` 또는 저장소 최상위 `PC_공동저장_실행.bat`
- 데이터: 기본 `~/.hdc-permit-data/permit.sqlite3` 및 `~/.hdc-permit-data/attachments/`
- Python 3.10 이상만 있으면 별도 패키지 설치 없이 실행할 수 있습니다.

## 켜고 끄는 방식

처음 실행할 때 관리자 비밀번호(6자 이상)를 PC의 프로그램 창에 직접 입력합니다. 비밀번호는 서버의 SQLite 데이터베이스에 해시로 저장되며 GitHub에 올리지 않습니다.

PC 서버가 켜지면 접속 주소가 표시되고 내 PC에서는 `http://127.0.0.1:8765/`로 접속합니다. 같은 사내망의 다른 PC에서는 실행창에 표시되는 `http://<PC의 사내 IP>:8765/` 주소를 사용합니다. 연결이 차단되면 Windows 방화벽의 사내망 접속 허용 여부를 전산 정책에 따라 확인해야 합니다.

프로그램을 종료하거나 PC 전원을 꺼도 데이터베이스 파일과 첨부파일은 삭제되지 않습니다. 다시 실행하면 기록이 그대로 남아 있습니다. PC가 꺼져 있거나 절전 상태이면 직원들은 접속할 수 없습니다.

**GitHub Pages 주소는 별도의 시연 화면으로 유지됩니다.** GitHub Pages의 HTTPS 화면에서 사내 PC의 HTTP 서버에 바로 접속하는 방식은 브라우저 보안 제약이 있으므로, PC 서버가 제공하는 자체 웹주소로 접속해야 합니다.

## 직원의 첫 로그인

직원은 **별도 회원가입이 필요 없습니다.** 처음 접속할 때 회사 이메일 ID(`@hdc-resort.com` 앞부분)와 테스트용 비밀번호(6자 이상)를 입력하고 **로그인**을 누르면, 사용하지 않은 ID인 경우 일반 직원 계정이 자동 생성됩니다. 이후에는 동일한 ID와 비밀번호로 로그인합니다. 기존 계정의 잘못된 비밀번호를 입력하더라도 계정을 새로 만들거나 비밀번호를 초기화하지 않습니다.

관리자 계정은 기존 정보를 유지합니다. 인허가팀 검토 권한은 관리자만 발급합니다.

**중요:** 현재는 메일 본인확인을 하지 않으므로 다른 사람이 먼저 임의의 ID를 사용할 수 있습니다. 이 자동 생성 기능은 PC 테스트 실행기에서만 활성화됩니다. **실제 회사 자료에는 사용하지 말고**, 운영 전 회사 이메일 인증 또는 사내 계정 연동이 반드시 필요합니다.

## 관리자가 기존 계정의 인허가팀 권한을 지정하는 방법

1. 직원이 본인의 회사 이메일 ID와 테스트용 비밀번호로 **최초 로그인**하면 일반 직원 계정이 자동으로 생성됩니다.
2. 관리자 계정으로 로그인하여 왼쪽 **관리자 설정 → 직원 계정 목록 · 권한 관리**를 확인합니다.
3. 생성된 계정의 이메일, 등록일, 현재 권한을 보고, 해당 직원의 신원을 직접 확인한 다음 **인허가팀으로 지정**을 누릅니다.
4. 관리자의 본인 비밀번호를 다시 입력하면 해당 계정이 인허가팀 권한으로 변경됩니다. 직원의 기존 비밀번호, 접수 및 회신 기록은 유지됩니다.
5. 권한을 바꾼 직원은 새 권한의 화면을 보기 위해 다시 로그인합니다. **일반 직원으로 변경** 버튼으로 권한을 회수할 수도 있습니다.

계정 신규 등록 양식을 관리자 화면에서 제거했습니다. 권한 변경은 관리자만 가능하고, 대상 계정의 이전 로그인 세션을 종료하며, 변경 이력이 남습니다. **이메일 주소를 입력했다고 회사 소속이 검증되지는 않으므로 반드시 사람과 계정의 소유자를 확인하세요.**

## 비밀번호를 잊은 직원의 초기화

1. 로그인 화면 아래 **비밀번호를 잊으셨나요? 인허가팀 관리자에게 초기화를 요청하세요** 안내가 나옵니다.
2. 직원이 관리자에게 직접 문의하고 본인 확인을 받습니다.
3. 관리자가 **관리자 설정 → 직원 비밀번호 초기화**에서 이메일을 검색해 계정을 선택합니다.
4. 관리자의 본인 비밀번호를 다시 입력해 초기화합니다. 시스템은 새 임시 비밀번호를 **한 번만** 보여줍니다.
5. 관리자는 임시 비밀번호를 직원에게 별도 경로로 전달하고, 직원은 임시 비밀번호로 로그인합니다.
6. 로그인 즉시 **새 비밀번호(6자 이상)**로 변경해야 업무를 볼 수 있습니다.

초기화 시 기존 로그인 세션은 해제되고 직원의 접수·회신·첨부파일은 지워지지 않습니다. 시스템에는 임시 비밀번호의 평문이 저장되지 않으며, 초기화·변경 이력만 기록합니다. **관리자 자신의 비밀번호 초기화는 별도 관리 절차가 필요합니다.** 관리자용 기능은 직원의 실제 신원을 직접 확인한 후 사용하세요.

## 회사 메일 자동발송 연동

현재 접수·회신 처리 시 자동발송 기능이 호출되도록 구현했습니다.

- **요청 접수:** 인허가팀 공용 메일주소에 접수번호, 요청부서, 제목을 알립니다. 첨부파일은 이메일에 실어 보내지 않고 시스템에서 확인합니다.
- **검토 결과 확정:** 요청한 직원에게 검토분야, 회신자, 검토 결과, 법령 근거 및 후속 조치를 보냅니다.
- **전송 기록:** `mail_events` 데이터베이스에 `accepted`(SMTP 서버 접수), `failed`(실패), `not_configured`(미연결)로 남습니다. 성공한 SMTP 접수가 반드시 수신자의 편지함 도착을 보장하지는 않습니다. 메일 발송 실패해도 업무 접수·회신 저장은 취소되지 않습니다.

**기본적으로 실제 발송은 꺼져 있습니다.** 회사 내부 메일 시스템에 대한 승인을 받은 뒤 서버 담당자가 **서버 환경변수로만** 아래 정보를 설정해야 합니다. 이 공개 GitHub 저장소나 ChatGPT 대화에 비밀번호를 올리지 마세요.

| 환경변수 | 내용 |
|---|---|
| `PERMIT_MAIL_ENABLED` | 회사 승인 및 검증 후 `1` |
| `PERMIT_SMTP_HOST` | 회사에서 허용한 SMTP 발송 서버 주소 |
| `PERMIT_SMTP_PORT` | 포트 (기본 STARTTLS 587, SMTP SSL 465) |
| `PERMIT_SMTP_SECURITY` | `starttls` 또는 `ssl` |
| `PERMIT_SMTP_USER` | 회사에서 발급한 발송 계정 (SMTP 인증 시) |
| `PERMIT_SMTP_PASSWORD` | 발송 인증 비밀정보 (SMTP 인증 시) |
| `PERMIT_MAIL_FROM` | 승인된 시스템 발신주소 (`@hdc-resort.com`) |
| `PERMIT_TEAM_MAIL` | 알림을 받을 인허가팀 공용주소 (`@hdc-resort.com`) |

현재 PC 테스트 실행기는 `PERMIT_ENABLE_TEST_AUTO_ACCOUNT=1`로 실행되기 때문에 **메일 설정을 임의로 넣더라도 실제 발송하지 않도록 차단합니다.** 이메일 소유권을 검증하지 않는 자동계정 상태에서 메일을 무단 전송하지 않도록 하기 위한 조치입니다.

**내일 전산실 확인:** 사내 AI 프로그램들이 메일을 보내는 방식이 승인된 SMTP인지 Microsoft Graph/사내 API인지 먼저 확인하세요. SMTP를 지원한다면 위 설정으로 연결할 수 있습니다. Graph/사내 API만 사용 가능하면 발송 연결 모듈을 해당 API 방식으로 바꿔야 하며, 현재는 그 부분까지 연결되지 않았습니다. 운영환경은 HTTPS와 회사 SSO·계정 인증, 보안 승인 및 서버 백업이 필요합니다.

## 테스트와 실제 업무자료의 구분

현재 PC 버전은 **사내 파일럿용 HTTP 서버**입니다. 브라우저를 통해 보내는 비밀번호와 자료가 HTTPS로 암호화되지 않으므로 **실제 회사 비밀번호나 기밀 인허가 자료를 입력해서는 안 됩니다.** 가상 자료 및 임시 테스트 암호만 사용하세요.

실제 운영 단계에는 사내 전산팀의 허용 정책, HTTPS, 방화벽 접근제한, 암호·권한 점검, 정기 백업, 복구 점검 등이 필요합니다. 윈도우 방화벽을 전체 비활성화하면 안 됩니다. 데이터가 중요한 경우 `permit.sqlite3` DB 파일과 `attachments` 폴더를 함께 백업하세요(가능하면 서버 종료 후 파일 복사).

## 구현 기능

- PC 테스트 서버에서는 직원이 **첫 로그인할 때 계정 자동 생성**, 관리자가 생성 계정을 보고 인허가팀 권한 부여/회수
- 여러 직원이 공유하는 SQLite 검토 요청 / 접수번호 / 검토 초안 / 최종 회신
- 첨부파일 저장, 사진과 PDF 미리보기
- 요청자별 조회 제한과 인허가팀 전체 조회
- 접수, 첨부, 검토, 회신 변경이력 저장
- 테스트: `python -m unittest discover -s server -v`

실제 이메일 자동 발송, 통합 로그인, HTTPS 운영환경은 아직 연결되지 않았습니다.
